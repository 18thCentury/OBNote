**ai**:  Zephyr RTOS 的 **SYS_INIT** 是一种静态初始化机制，用于在系统启动过程中按预定顺序自动执行初始化代码。它构成了 Zephyr 驱动模型和子系统启动的核心基础设施。

## 1. 初始化级别 (Initialization Levels)

SYS_INIT 将初始化过程划分为四个严格顺序的阶段：

| 级别 | 宏定义 | 执行时机 | 典型用途 |
| --- | --- | --- | --- |
| PRE_KERNEL_1 | `PRE_KERNEL_1` | 内核启动前，中断未使能 | 中断控制器、早期 UART、定时器硬件 |
| PRE_KERNEL_2 | `PRE_KERNEL_2` | 内核启动前，中断已使能 | 依赖中断的硬件初始化 |
| POST_KERNEL | `POST_KERNEL` | 内核完全启动后 | 需要线程/调度器的驱动（I2C、SPI 等）|
| APPLICATION | `APPLICATION` | 应用主函数前 | 应用层子系统、网络栈等 |

## 2. 优先级与排序机制

在同一级别内，通过**优先级数值**（0-99）控制执行顺序：

- **数值越小，优先级越高**（0 最先执行）
- 相同优先级的初始化函数**不保证顺序**

```c
// 示例：高优先级（先执行）
SYS_INIT(my_early_init, POST_KERNEL, 10);

// 示例：低优先级（后执行）
SYS_INIT(my_late_init, POST_KERNEL, 90);
```

## 3. 实现架构

### 链接器段 (Linker Sections)
SYS_INIT 利用链接器脚本将初始化函数指针放入特定的只读数据段：

- `.z_init_PRE_KERNEL_1_*`
- `.z_init_PRE_KERNEL_2_*`
- `.z_init_POST_KERNEL_*`
- `.z_init_APPLICATION_*`

### 运行时遍历
内核启动代码通过 `z_cstart()` → `do_device_init()` 遍历这些段，按顺序调用函数：

```c
// 简化的执行逻辑
extern struct init_entry __init_start[];
extern struct init_entry __init_end[];

for (struct init_entry *entry = __init_start; 
     entry < __init_end; entry++) {
    if (entry->init_fn) {
        entry->init_fn();
    }
}
```

## 4. 使用示例

### 基础用法
```c
#include <zephyr/init.h>

static int my_subsystem_init(void)
{
    // 初始化代码
    return 0;  // 返回 0 表示成功
}

// 注册为 POST_KERNEL 级别，优先级 50
SYS_INIT(my_subsystem_init, POST_KERNEL, 50);
```

### 带参数的初始化（现代用法）
```c
// 使用 SYS_INIT_NAMED 或配合设备树
static int my_driver_init(const struct device *dev)
{
    // 设备特定初始化
    return 0;
}

SYS_INIT(my_driver_init, POST_KERNEL, CONFIG_MY_DRIVER_INIT_PRIORITY);
```

## 5. 与设备驱动模型的关系

现代 Zephyr 推荐使用 **DEVICE_DT_DEFINE** 宏，它内部同样基于 SYS_INIT 机制，但增加了设备树集成：

```c
// 底层仍是 SYS_INIT 机制
DEVICE_DT_DEFINE(dt_node, init_fn, pm_control_fn,
                 data_ptr, cfg_ptr, level, prio, api_ptr);
```

**关键区别**：
- **SYS_INIT**：用于纯软件子系统或不对应具体硬件设备的初始化
- **DEVICE_DEFINE**：用于具有设备树节点的硬件设备，自动处理依赖关系

## 6. 依赖管理

Zephyr 通过 **CONFIG_*_INIT_PRIORITY** Kconfig 选项管理跨模块的初始化顺序：

```kconfig
# Kconfig
config SENSOR_INIT_PRIORITY
    int "Sensor initialization priority"
    default 90
    depends on SENSOR
```

然后在驱动中使用：
```c
SYS_INIT(sensor_init, POST_KERNEL, CONFIG_SENSOR_INIT_PRIORITY);
```

这种设计允许用户通过 menuconfig 调整驱动加载顺序，解决初始化依赖冲突。

## 总结

SYS_INIT 是 Zephyr 的**声明式启动架构**，通过编译时收集初始化函数、链接时排序、运行时顺序执行的机制，实现了模块化系统的自动组装，避免了传统 RTOS 中手动编写启动代码的繁琐和易错性。
