
nanobot 的代码结构非常清晰：

```
nanobot/
├── agent/          # 🧠 Core agent logic
│   ├── loop.py     #    Agent loop (LLM ↔ tool execution)
│   ├── context.py  #    Prompt builder
│   ├── memory.py   #    Persistent memory
│   ├── skills.py   #    Skills loader
│   ├── subagent.py #    Background task execution
│   └── tools/      #    Built-in tools (incl. spawn)
├── skills/         # 🎯 Bundled skills (github, weather, tmux...)
├── channels/       # 📱 WhatsApp integration
├── bus/            # 🚌 Message routing
├── cron/           # ⏰ Scheduled tasks
├── heartbeat/      # 💓 Proactive wake-up
├── providers/      # 🤖 LLM providers (OpenRouter, etc.)
├── session/        # 💬 Conversation sessions
├── config/         # ⚙️ Configuration
└── cli/            # 🖥️ Commands
```

从架构设计角度看，nanobot 采用了**分层模块化**的组织方式，这种结构体现了清晰的关注点分离（Separation of Concerns）和可插拔架构思想：

## 核心认知层 [agent/](app://obsidian.md/agent/)

这是 nanobot 的"大脑"，约 800 行代码集中处理 Agent 的本质逻辑：

- **[agent/loop.py](app://obsidian.md/agent/loop.py)** - 主决策循环，相当于认知中枢，负责思考-行动-观察的循环
- **[agent/context.py](app://obsidian.md/agent/context.py)** - Prompt 工程层，管理上下文窗口和记忆注入
- **[agent/memory.py](app://obsidian.md/agent/memory.py)** - 持久化记忆系统（Markdown + JSONL 双格式），实现长期记忆
- **[agent/skills.py](app://obsidian.md/agent/skills.py)** - 技能注册与加载机制，动态发现可用工具
- **[agent/subagent.py](app://obsidian.md/agent/subagent.py)** - 异步任务执行，支持后台思考不阻塞主流程
- **[agent/tools/](app://obsidian.md/agent/tools/)** - 原子能力集合，最基础的执行单元

## 能力扩展层 [skills/](app://obsidian.md/skills/)

与 [agent/tools/](app://obsidian.md/agent/tools/) 不同，这里的技能是**高阶复合能力**：

- 每个技能（如 [skills/github/](app://obsidian.md/skills/github/)、[skills/weather/](app://obsidian.md/skills/weather/)）都是独立模块
- 通过 [agent/skills.py](app://obsidian.md/agent/skills.py) 动态加载，实现热插拔
- 这种设计让功能扩展不需要修改核心代码

## 交互适配层 [channels/](app://obsidian.md/channels/)

隔离了具体的消息平台细节：

- [channels/telegram/](app://obsidian.md/channels/telegram/)、[channels/whatsapp/](app://obsidian.md/channels/whatsapp/)、[channels/feishu/](app://obsidian.md/channels/feishu/) 各自处理协议差异
- 统一转换为内部事件，向上层屏蔽通信细节

## 基础设施层

- **[providers/](app://obsidian.md/providers/)** - LLM 提供商的适配器模式，支持 OpenRouter、Anthropic、OpenAI、vLLM 等，便于切换模型或负载均衡
- **[bus/](app://obsidian.md/bus/)** - 消息总线，解耦生产者和消费者，支持事件驱动架构
- **[cron/](app://obsidian.md/cron/)** - 定时任务调度，让 Agent 具备"主动性"
- **[gateway/](app://obsidian.md/gateway/)** - 对外服务网关，处理认证、限流等横切关注点

## 设计哲学

这种结构让 nanobot 具备**洋葱架构**特征：

- 核心（[agent/](app://obsidian.md/agent/)）不依赖外层，只依赖抽象
- 外层（[channels/](app://obsidian.md/channels/)、[skills/](app://obsidian.md/skills/)）通过接口与核心交互
- [bus/](app://obsidian.md/bus/) 作为事件中枢，实现模块间松耦合通信

简言之，这是一个**以 Agent 为核心、事件驱动、可水平扩展**的 AI 应用架构，既保持了核心逻辑的简洁（800 行），又通过插件机制支持无限功能扩展。
