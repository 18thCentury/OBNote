在 OpenClaw 框架中，针对不同模型（如 **DeepSeek-V3/R1** 或 **GPT-4o**）进行 Prompt 优化，核心在于理解它们对**结构化指令**和**工具调用机制**的偏好差异。

以下是针对这两类主流模型的优化实战技巧：

---

### 1. 针对 DeepSeek (V3/R1) 的优化

DeepSeek 模型（尤其是 R1）擅长逻辑推理，但在工具调用稳定性上，有时需要更明确的 XML 格式或思维链引导。

- **强化思维链 (CoT) 引导**：
    
    DeepSeek 对 `<thinking>` 标签非常敏感。在 System Prompt 中强制要求它在调用工具前进行思考，能显著降低“幻觉”调用。
    
    > **Prompt 技巧**：`在输出 Action 之前，必须先在 <thinking> 标签内分析：1. 用户意图 2. 是否需要外部数据 3. 参数是否完整。`
    
- **使用 XML 模式替代纯 JSON**：
    
    虽然 DeepSeek 支持 JSON，但实验表明它在处理嵌套复杂的工具参数时，使用类 HTML/XML 标签（如 `<tool_call>`）的解析成功率更高。
    
- **处理“重复调用”问题**：
    
    DeepSeek 偶尔会出现循环调用同一个工具的情况。
    
    > **优化方案**：在 Prompt 中加入：`如果 Observation 已经包含所需信息，禁止重复调用相同工具，请直接进入 Final Answer。`
    

---

### 2. 针对 GPT-4o 的优化

GPT-4o 对 OpenAI 原生的 **Function Calling (Tools)** 协议支持极好，因此优化重心在于**节省 Token** 和**处理多步规划**。

- **Schema 扁平化**：
    
    GPT-4o 处理深层嵌套的 JSON Schema 会消耗更多推理资源且易错。
    
    > **优化前**：`{"user": {"location": {"city": "上海"}}}`
    > 
    > **优化后**：`{"city": "上海"}` (尽量将参数平铺)。
    
- **利用 Prompt Caching (缓存)**：
    
    OpenClaw 的 System Prompt 通常很长（包含大量工具描述）。由于 GPT-4o 支持 Prompt Caching，**将不常变动的工具定义放在 Prompt 的最开头**，可以大幅降低成本。
    
- **少样本示例 (Few-Shot)**：
    
    GPT-4o 是“模仿大师”。提供 1-2 个复杂的 `Thought -> Action -> Observation -> Final Answer` 完整示例，能让它的回复格式极其稳定。
    

---

### 3. OpenClaw 通用的“模块化”优化技巧

OpenClaw 引入了一些独特的机制来优化所有模型的效果：

- **SOUL.md 与 SKILL.md (模块化注入)**：
    
    不要把所有指令塞进一个 System Prompt。OpenClaw 支持通过 `SOUL.md` 定义人格，通过 `SKILL.md` 动态注入工具说明。
    
    - **效果**：模型只有在需要用到某项技能时才会读取相关的 Prompt，减少了上下文噪声。
        
- **严格的负面约束**：
    
    在 OpenClaw 中，明确告诉模型“什么时候**不准**用工具”比告诉它“怎么用”更重要。
    
    > `Constraint: 如果用户只是在打招呼或闲聊，严禁调用任何 API。`
    

---

### 4. 总结对比表

|**优化维度**|**DeepSeek (推理导向)**|**GPT-4o (协议导向)**|
|---|---|---|
|**首选格式**|XML 标签或结构化文本|原生 JSON / Tools 协议|
|**思维引导**|强制 `<thinking>` 过程|侧重 Few-shot 示例|
|**参数复杂度**|擅长处理逻辑关联的参数|建议扁平化以节省 Token|
|**稳定性技巧**|明确禁止循环调用|利用 Prompt Caching 降费|
