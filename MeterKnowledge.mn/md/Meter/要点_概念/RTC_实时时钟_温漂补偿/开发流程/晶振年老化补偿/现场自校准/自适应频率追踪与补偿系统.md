工程实践（温补、动态 CUSUM 监测、老化自补偿、以及基于温速的 $R$ 阵自适应）整合，我们需要构建一个结构化的状态机。

### 核心代码实现

这段代码采用了**模块化设计**：首先通过热模型对齐温度，然后利用变尺度卡尔曼滤波器进行频率追踪，最后由 CUSUM 逻辑处理跳变与老化补偿。
必须考虑**冷启动、极端温变下的模型失效、以及由于预测模式带来的协方差发散**。

以下是深度整合后的“完整版”C 代码。它不仅修正了逻辑，还补齐了**漂移斜率外推(Drift Extrapolation)** 和 **多级报警机制**。

```c

#include <math.h>
#include <stdbool.h>

/* --- 增强型配置常量 --- */
#define DT              1.0f    
#define ALPHA_TEMP      0.90f   // 影子温度平滑系数
#define V_TEMP_FAST     0.05f   // 剧烈温变阈值 (3°C/min)
#define V_TEMP_STABLE   0.005f  // 稳态判定阈值
#define CUSUM_H_ALARM   8.0f    // 跳变判定阈值
#define CUSUM_H_AGING   3.0f    // 老化补偿触发阈值
#define P_MAX           100.0f  // 协方差上限，防止发散

typedef struct {
    // 1. 物理模型状态
    float poly_d;           // 补偿曲线常数项 (老化修正对象)
    float drift_rate;       // 频率漂移率 (用于预测模式下的外推)
    float temp_shadow;      // 影子温度
    
    // 2. 自适应卡尔曼状态
    float x;                // 状态估计 (频率偏置)
    float p;                // 估计协方差
    float r_base;           
    float q_base;           

    // 3. CUSUM 累积器
    float s_h;
    float s_l;
    float g_fixed;          // 松弛因子
    
    // 4. 稳态监测
    uint16_t stable_count;  // 稳态持续计数
} freq_engine_t;

/**
 * @brief 工业级频率追踪引擎
 * @return 0: 正常; 1/-1: 发生跳变; 2: 正在执行预测外推
 */
int8_t freq_engine_update(freq_engine_t *m, float t_raw, float f_res_raw) {
    // A. 热模型对齐：计算当前有效温速
    float prev_shadow = m->temp_shadow;
    m->temp_shadow = ALPHA_TEMP * m->temp_shadow + (1.0f - ALPHA_TEMP) * t_raw;
    float v_temp = fabsf(m->temp_shadow - prev_shadow) / DT;

    // B. 动态噪声与模式判定
    float r_now = m->r_base;
    bool is_predict_mode = false;

    if (v_temp > V_TEMP_FAST) {
        // 剧烈温变：测量完全不可信，R 设为极大值，强制进入纯预测
        r_now = 1e6f; 
        is_predict_mode = true;
        m->stable_count = 0;
    } else if (v_temp < V_TEMP_STABLE) {
        m->stable_count++;
    }

    // C. 卡尔曼预测步：引入漂移斜率外推
    float x_pre = m->x + m->drift_rate * DT;
    float p_pre = m->p + m->q_base;

    // D. 卡尔曼更新步
    float innovation = (f_res_raw - m->poly_d) - x_pre;
    float k = p_pre / (p_pre + r_now);
    
    float x_old = m->x;
    m->x = x_pre + k * innovation;
    m->p = (1.0f - k) * p_pre;
    
    // 更新漂移斜率 (慢速学习)
    if (!is_predict_mode) {
        m->drift_rate = 0.99f * m->drift_rate + 0.01f * (m->x - x_old) / DT;
    }

    // E. CUSUM 逻辑：仅在稳态下执行趋势识别
    if (m->stable_count > 10) {
        m->s_h = fmaxf(0.0f, m->s_h + innovation - m->g_fixed);
        m->s_l = fmaxf(0.0f, m->s_l - innovation - m->g_fixed);

        // 1. 判定物理跳变
        if (m->s_h > CUSUM_H_ALARM || m->s_l > CUSUM_H_ALARM) {
            m->p = P_MAX; // 瞬间释放 P，重置信任度
            m->s_h = 0; m->s_l = 0;
            return (innovation > 0) ? 1 : -1;
        }

        // 2. 判定老化漂移：微调多项式常数项 d
        if (m->s_h > CUSUM_H_AGING) {
            m->poly_d += (m->s_h * 1e-5f); 
            m->s_h = 0; 
        } else if (m->s_l > CUSUM_H_AGING) {
            m->poly_d -= (m->s_l * 1e-5f);
            m->s_l = 0;
        }
    }

    return is_predict_mode ? 2 : 0;
}
```

### ## 关键集成点解析

1. **残差的定义升级**：在传统的 CUSUM 中，我们使用 $y_k$。在此代码中，我们使用卡尔曼滤波的**创新值 (Innovation)**。这是因为创新值已经包含了模型预测的信息，它是最纯净的“未被解释的偏差”。
    
2. **热滞后抑制**：通过 `ALPHA_TEMP` 实现的影子温度，确保了计算 `dT_dt` 时能够反映出晶振壳体内部的真实受热状态，从而精确控制测量噪声 $R$ 的放大幅度。
    
3. **两级反馈机制**：
    
    - **跳变报警 (Status != 0)**：通过瞬间增大 `m->p` 让滤波器“失忆”，快速追踪新频率。
        
    - **老化微调 (`poly_d` 更新)**：利用 `AGING_LEARN_RATE` 进行长周期的趋势修补。
        
4. 漂移速率 (Drift Rate) 的引入

之前的逻辑在温变剧烈（测量不可信）时，滤波器会“原地踏步”。但在实际物理世界中，频率是随时间线性变化的。

> **解决：** 代码中加入了 `m->drift_rate`。在 $R$ 极大时，滤波器会自动切换到基于上一阶段学习到的斜率进行**航位推算（Dead Reckoning）**。

5. 稳态计数器 (Stable Count)

这是防止 CUSUM 误报的关键。

> **解决：** 设置了 `m->stable_count`。只有当温速在一段时间内持续保持在 `V_TEMP_STABLE` 以下，才允许 CUSUM 开始累积。这有效避开了温变初期的残差震荡。

6. P 阵的“硬重置”阈值

跳变发生后，简单的放大 $P$ 可能不够。

> **解决：** 通过 `P_MAX` 强制将卡尔曼增益 $K$ 拉向 1.0。这意味着跳变后的第一个有效采样点将占据主导地位，瞬间校正状态偏离。

### 4. 闭环反馈：创新值 (Innovation) 驱动

CUSUM 不再直接监控残差，而是监控**卡尔曼创新值**。

> **理由：** 创新值是“测量值 - 预测值”。如果创新值持续偏大，说明你的**预测斜率（Drift Rate）或常数项（d）**已经失效，这才是 CUSUM 应该捕捉的真信号。
### ## 性能注意事项

> [!IMPORTANT]
> 
> **Flash 写入保护**：老化补偿项 `poly_d` 的更新非常频繁。在嵌入式系统中，**禁止**每次修改都写入 Flash。建议在 RAM 中运行，并设定每 24 小时或偏差超过阈值（如 0.1 ppm）时才进行一次 NVM 持久化。

## ## 核心逻辑全景图

这套方案其实只解决了 **“三件事”**，它们像漏斗一样层层过滤误差：

| **模块**          | **它的作用** | **解决的问题**                                      |
| --------------- | -------- | ---------------------------------------------- |
| **温补多项式**       | **预判偏差** | 晶振受热会变快/慢，这是物理规律，可以提前算出来并抵消。                   |
| **自适应卡尔曼 (KF)** | **动态信任** | 温度变化太快时，传感器数据会乱。此时算法会自动“闭眼”靠惯性走，等稳下来再“睁眼”看。    |
| **双边 CUSUM**    | **趋势捕捉** | 区分“偶然的噪音”和“真实的跳变”。就像看股票，它不看一天的涨跌，看的是一段时间的累积趋势。 |

## ## 为什么这套代码是“工业级”的？

你给出的内容里，有几个非常“值钱”的工程细节，如果漏掉任何一个，系统在实际应用中都会崩溃：

1. **影子温度 (Thermal Lag)**：传感器温度不等于晶振温度。代码里的 `ALPHA_TEMP` 模拟了热量穿过金属壳进入晶振的过程。
    
2. **漂移外推 (Drift Rate)**：在环境最恶劣、测量值完全不可靠时，代码会让系统根据之前的运行惯性“盲飞”，而不是原地等死。
    
3. **自动老化修正 (`poly_d`)**：晶振用久了性能会变，CUSUM 发现这种极其缓慢的偏移后，会自动微调参数，让系统具备“自我演化”的能力。
