让我们拆解一下业界（如海兴、威胜等大厂）在 PCF8563 这种硬件条件下，如何处理 `Error_ns`。

---

### 1. 为什么需要“分摊”？（锯齿波 vs. 直线）

如果你每 $1\text{s}$ 计算一次 `Error_ns`（比如算出来快了 $1000\text{ns}$），然后瞬间在 `system_ns` 上加 $1000$：

- **宏观上看**：误差确实补回来了，长期精度没问题。
    
- **微观上看**：在这一秒的末尾，时间轴发生了一个 $1\mu s$ 的“瞬时跳变”。如果电表的采样脉冲正好落在这个跳变点，瞬时功率计算就会出现一个小的毛刺。
    

**业界做法**：将这个 $1000\text{ns}$ 像撒盐一样，均匀撒在下一秒的每一个计数周期里。

---

### 2. 业界电表实际如何计算 `Error_ns`？

业界电表通常不使用“死等 1 秒”的逻辑，而是使用 **“分数步进法”**。

#### A. 补偿周期

- **温度采样周期**：通常为 **$5 \sim 10$ 秒**一次（因为环境温度变化极慢）。
    
- **PPM 计算周期**：与温度采样同步。
    
- **补偿应用周期**：**每一周期（Tick）**。
    

#### B. 核心算法：分数累加器（Fractional Accumulator）

不需要额外的 $1\text{ms}$ 中断，你现有的那个驱动 `system_ns` 的中断（假设是 $10\text{ms}$ 或 $100\text{ms}$）就可以。

**逻辑如下：**

1. **定义标准步长**：如果中断是 $10\text{ms}$，标准增量 $Step_{base} = 10,000,000 \text{ ns}$。
    
2. **计算微偏增量**：根据当前 $PPM$，计算出每一个 $10\text{ms}$ 应该多加或少加多少纳秒。
    
    $$Step_{adj} = Step_{base} \times (1 + \frac{PPM_{total}}{1,000,000})$$
    
3. **实时累加**：
    
    在中断服务程序（ISR）中：
    
    `system_ns += Step_adj;`
    

**这样做的结果**：你的 `system_ns` 每一刻都在以“修正后”的速度匀速增长。你不需要每隔 1 秒去修正它，因为它从出生那一刻起，步子的大小就是经过温补校准的。

---

### 3. 具体的代码实现模型（定点化）

为了避免浮点运算，业界常用 **“Q24 格式”或“放大法”**。

C

```
// 假设你的中断周期是 10ms (即 10,000,000 ns)
#define BASE_STEP_NS 10000000LL

// 1. 每 10 秒更新一次温度和补偿因子
if (ten_sec_flag) {
    int32_t ppm = calculate_ppm(temp); // 得到当前 PPM 值
    // 计算每 10ms 对应的纳秒偏移量 (放大 1000 倍防止丢弃小数)
    // offset_per_tick = ppm * 10000000 / 1000000 = ppm * 10
    tick_offset_ns = ppm * 10; 
}

// 2. 在你的定时器中断里 (每 10ms 执行一次)
void Timer_ISR(void) {
    // 这里的 system_ns 永远是平滑的直线增长
    system_ns += (BASE_STEP_NS + tick_offset_ns);
    
    // 如果需要更新 ADC 采样率，也在这里根据 tick_offset_ns 调整寄存器
}
```

---

### 4. 总结你的疑问

- **一定要 $1\text{ms}$ 中断吗？**
    
    不一定。只要是驱动你 `system_ns` 递增的那个源（中断）就可以。
    
- **计算 `Error_ns` 的周期？**
    
    - **计算系数（PPM）**：$5 \sim 10$ 秒一次。
        
    - **执行补偿（加减纳秒）**：**每一次中断都要加**。
        
- **这样做的好处**：
    
    你的 `system_ns` 永远领先于或同步于物理世界，没有任何跳变。电表的能耗脉冲、功率积分、时段切换，全部基于这个丝滑的时间轴。
