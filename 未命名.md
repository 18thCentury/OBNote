我打算开发一个软plc采集器,
目前有初步想法,你以工业化的经验,业界方案做参考,完善:

零. 设计目标:软plc采集卡
1.采集数据
	- 采集 udp json 数据.
	- 采集 modbus tcp 数据
	- 采集 opcua 数据
	- 采集io 计数数据
2. 用户配置
	- json 解析,配置json格式(key-value组),提取部分key-value ,mqtt上传到server(json格式)
		> 例如: {"Alarm":"TipErr","MoldNo.":"1021","Time":"2016-12-12 20:12:50","Encode":"GB2312"}
		> 注释:采用jsmn解析
	- modbus tcp 解析:[addr,len,解析方式(str,int,float等)],组json(name-value),上传
	- opcua 解析:[namespace,addr],组json(name-value),上传.
	
一. 硬件平台:
	stm32f207,freertos,lwip,128kB fram.

二. 架构设计
1. 映像寄存器区 (I/O Image Table): 建立一个全局缓冲区(DB 区)。所有的工业协议(S7、Modbus 等)采集到的数据都映射到这个缓冲区。用户编写的逻辑只操作缓冲区，不直接操作底层协议。
开辟几块连续的内存:**V、I、Q、M、AI、AQ** 区。

| 区域符号        | 完整名称                   | STM32 分配大小                    | 访问方式       | 用途                                                                                           |
| ----------- | ---------------------- | ----------------------------- | ---------- | -------------------------------------------------------------------------------------------- |
| **I**       | Process Input          | 128 Bytes (I0.0 - I127.7)     | 位/字节/字     | 本地 DI + 协议采集位 (JSON/Modbus 开关)                                                               |
| **Q**       | Process Output         | 128 Bytes (Q0.0 - Q127.7)     | 位/字节/字     | 本地 DO + 控制远程设备                                                                               |
| **V**       | Variable Memory        | **4096 Bytes** (VB0 - VB4095) | 位/字节/字/双字  | **核心：** 所有 Modbus/OPCUA 采集的数据均映射到此                                                           |
| **M**       | Internal Marker        | 256 Bytes (M0.0 - M255.7)     | 位/字节/字     | 中间逻辑位、控制标志                                                                                   |
| **AI/AQ**   | Analog I/O             | 各 64 Words                    | 字 (16-bit) | 模拟量输入输出映射                                                                                    |
| **V-Cache** | Shadow Variable Memory | ** 4096 Bytes**               | 位/字节/字/双字  | **核心：** 所有 Modbus/OPCUA 采集的数据均写到此,每个周期同步到V,在映射到 V 区时，提供配置选项：ABCD, BADC, CDAB, DCBA 四种字节交换模式， |
|             |                        |                               |            |                                                                                              |
|             |                        |                               |            |                                                                                              |

注:v区添加数据质量位区域,标识数据是否有效

2. 协议处理模块:(独立任务运行，它们将结果写入“后台缓冲区”，逻辑解析器只读取“快照”)
	s7 client
		-(只采集DB的简化协议)
	modbus tcp client
	opcua client
		-(因f207的限制,轻量简化版,仅支持二进制编码(Binary Encoding)，放弃 XML/JSON 编码,不处理复杂的 Browse、不带安全加密 None Security)
	mqtt client
	
3. 循环扫描调度 (Cyclic Scan):
	- 读取输入 
		- (io,s7,modbus,opcua),放到 MM_I
	- 执行逻辑 (逻辑解析器)
		- Watchdog:逻辑解析器必须在规定时间内完成。如果运行超时(如死循环)，立即复位并切断所有 Q 区输出。
	- 更新输出 
		- (io),数据放到 MM_O
	- 通信处理 
		- watchdog:
		- (调用mqtt上传)(log 发送到上位机)
	
4. 逻辑解析器:
	字节码指令集
	功能块
		- 系统自带(json_fb,mqtt_fb)
	
5. task设计:

| 优先级               | 任务名称                    | 周期        | 描述                                                       |
| ----------------- | ----------------------- | --------- | -------------------------------------------------------- |
| **最高(Real-time)** | **Local_IO_Task**       | 1ms       | 硬中断采集 IO，处理计数器                                           |
| **高**             | **Logic_Engine_Task**   | 10ms-50ms | 逻辑扫描周期，读取映像区 -> 执行字节码 -> 更新输出,必须是硬定时器触发，确保抖动(Jitter)在微秒级 |
| **高**             | **lwip_Task**           | 变动        | LwIP 协议栈处理                                               |
| **中**             | **Protocol_Stack_Task** | 变动        | Modbus/UDP/opcua 数据包收发                                   |
| **低**             | **Cloud_Task (MQTT)**   | 100ms+    | 组装 JSON 报文，发送至服务器                                        |
| **最低**            | **System_Diag**         | 500ms+    | 监控 CPU 负载、堆栈水位线、网络状态                                     |
