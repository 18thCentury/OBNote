“提示词工程”的重心已经变了。

像 [OpenAI Codex](https://openai.com/codex/?utm_source=chatgpt.com) 这一代带有“思考模式 / plan mode / agentic workflow”的模型，已经能自动补全大量以前必须手写的上下文结构。

以前：

- 模型弱
    
- 上下文窗口小
    
- 推理能力有限
    
- 工具调用差
    
- 长任务容易漂移
    

所以用户必须：

- 指定角色
    
- 指定步骤
    
- 强制 CoT（chain of thought）
    
- 写 SOP
    
- 手工拆任务
    
- 手工约束格式
    

否则结果会崩。

现在的大模型（GPT-5.x、Claude Opus 4、Gemini 2.5 Pro、Codex agent 类）已经具备：

- 自动任务分解
    
- 自动计划
    
- 长上下文关联
    
- 文件理解
    
- repo-level reasoning
    
- tool use
    
- self-correction
    

因此：

> “微操式提示词工程”正在快速贬值。

但：

> “上下文工程（Context Engineering）”正在快速升值。

这是现在最核心的变化。

---

# 一、过去的 Prompt Engineering 正在失效

以前流行的：

```text
你是一个资深架构师
请一步一步思考
不要遗漏任何细节
输出 markdown 表格
```

很多已经属于：

- 冗余
    
- placebo
    
- 甚至干扰
    

因为新模型默认已经：

- 会规划
    
- 会反思
    
- 会迭代
    
- 会检查
    

尤其开启：

- thinking
    
- deep research
    
- plan mode
    
- reasoning effort
    

后，模型内部已经在做大量隐式 CoT。

所以你会感觉：

> “我不怎么写提示词，它也能做得很好。”

这是能力跃迁，不是错觉。

---

# 二、现在真正重要的是：Context Engineering

今天高水平用户关注的不是“怎么写一句神 prompt”。

而是：

## 如何给模型“正确的工作环境”

这包括：

### 1. 正确上下文

比起：

```text
你是世界顶级专家
```

更重要的是：

```text
这是项目结构
这是 API
这是历史决策
这是约束
这是失败案例
这是目标
```

模型现在最吃的是：

- 信息质量
    
- 信息完整度
    
- 信息关联性
    

而不是“角色扮演文学”。

---

### 2. 正确任务边界

高手现在更像“技术负责人”。

不是告诉 AI：

- 怎么思考
    

而是告诉 AI：

- 什么是成功
    
- 什么不能做
    
- 什么优先级最高
    

例如：

```text
目标：
- 2周内上线 MVP
- 不允许引入新 infra
- 优先可维护性而不是性能
- 必须兼容现有 auth system
```

这种比：

```text
请仔细思考
```

价值高 100 倍。

---

### 3. 正确反馈循环

现代 AI 最大提升来自：

- iterative loop
    
- verify
    
- critique
    
- refine
    

不是“一发神 prompt”。

现在最佳实践是：

```text
1. AI先做
2. 人review
3. AI修正
4. AI继续推进
```

而不是：

```text
我必须第一次 prompt 就完美
```

这是旧时代思维。

---

# 三、2026 年最有效的方案是什么？

现在最强的方法不是 Prompt Engineering。

而是：

# 「Spec + Context + Iteration」

即：

## 1. Spec（规格定义）

清晰描述：

- 目标
    
- 输入
    
- 输出
    
- 约束
    
- 验收标准
    

例如：

```text
目标：
把 monolith 拆成 service

约束：
- 不停机
- 兼容旧 API
- PostgreSQL 不迁移

验收：
- p95 latency 不增加
- CI 全通过
```

这是第一优先级。

---

## 2. Context（上下文工程）

提供：

- repo
    
- 文档
    
- 历史代码
    
- 错误日志
    
- 架构图
    
- PR
    
- ADR
    

现代模型极度依赖真实上下文。

现在“喂资料”的重要性远大于“写技巧”。

---

## 3. Iteration（迭代）

不要幻想：

```text
一次生成 production code
```

真正高效的是：

```text
plan
→ draft
→ critique
→ patch
→ test
→ refine
```

这也是 Codex plan mode 本质在做的事。

---

# 四、那提示词还有没有价值？

有。

但位置变了。

现在提示词更像：

# “任务协议”

而不是：

# “魔法咒语”

高价值 prompt 现在通常用于：

---

## 1. 约束 AI

例如：

```text
不要修改 public API
不要新增依赖
先生成 plan 再改代码
```

这是非常重要的。

---

## 2. 指定评估标准

例如：

```text
优先：
1. 可维护性
2. 简洁
3. 性能
```

模型会明显改变决策。

---

## 3. 指定工作流

例如：

```text
先阅读整个 repo
列出风险
再开始修改
```

这是 agent orchestration。

---

## 4. 提供领域知识

模型再强：

- 也不了解你公司
    
- 不了解你的业务
    
- 不知道隐藏规则
    

这部分必须靠 prompt/context。

---

# 五、未来趋势：Prompt Engineering 会进一步消失

未来会越来越像：

```text
AI IDE + Agent OS
```

你做的是：

- 提供目标
    
- 提供上下文
    
- 提供反馈
    

AI负责：

- planning
    
- coding
    
- testing
    
- debugging
    
- refactoring
    

所以：

## “写 prompt”

会逐渐变成：

## “管理 agent”

这是根本变化。

---

# 六、现在真正拉开差距的人是谁？

不是：

- 会写华丽 prompt 的人
    

而是：

# 会构建 AI 工作流的人

包括：

- context management
    
- memory
    
- retrieval
    
- tooling
    
- eval
    
- verification
    
- repo organization
    
- task decomposition
    
- human-in-the-loop
    

未来的高手更像：

- AI Tech Lead
    
- AI Staff Engineer
    
- AI Workflow Architect
    

而不是“prompt magician”。

---

# 七、给你的一个实战建议（非常重要）

现在最值得建立的能力：

## 不再是：

```text
怎么写神 prompt
```

## 而是：

```text
怎么让 AI 持续稳定地产出
```

核心包括：

- repo 结构清晰
    
- 文档齐全
    
- spec 清晰
    
- feedback 快
    
- evaluation 自动化
    
- context 管理
    
- 测试完善
    

因为：

> AI 的上限，越来越取决于环境，而不是提示词技巧。

这就是为什么：

- Cursor
    
- Windsurf
    
- Codex
    
- Devin 类系统
    

都在拼：

- agent workflow
    
- memory
    
- tooling
    
- planning
    

而不是拼“prompt 模板”。

---

一句话总结：

> Prompt Engineering 没死，但已经从“技巧学”变成了“上下文与任务系统设计”。
